## Findings withdrawn after testing

These were in the earlier draft. Each was wrong, and the reason matters more than the retraction.

**W1 — "`includedLines` counts the omission notice, so `includedLines + omittedLines = lines + 1`."**
Withdrawn. `tests/manifest-accounting.test.js:87-101` reconciles `includedLines` against the fenced block
for **every file in every part**, and `docs/output.md:189-191` defines the field as "what the fenced block
holds". The counter is correct, documented and tested. Nothing claims the two numbers sum.
**What survives (Nit):** `docs/output.md:192`'s gloss "the number describes content, not rendering" is
false for a preview, where the counted lines include the notice; and `src/types.ts:385-394` documents
`incomplete[]`'s three numbers without saying which counts the notice.

**W2 — "Three floors for the minimum part budget, one silent."**
Withdrawn as a Medium. Every user-facing surface **throws**: `maxPartBytes`, `budgets.default` and
`budgets.byLayer[*]` all reject `< 4096` with the path and value named. The silent clamp is unreachable
from configuration.
**What survives (Nit):** `partitionFiles`, a public export, treats budgets 20/46/100/1000/2600
identically — a direct caller gets parts ~130× larger than asked for, with no error. Every other layer has
already been fixed: `config-budget.test.js:111` is titled "below the floor is a usage error, not a silent
clamp", and `enforceBudget` throws when it cannot hold the notice.

**W3 — "Three ownership predicates disagree."**
Withdrawn. The layering is deliberate: `isOurGeneratorName` answers *identification* (`index.ts:940,1021`,
`autopilot.ts:124`, `validate.ts:244`), while the **deletion** gate uses evidence — `index.ts:1238-1249`
filters entries against the marker's `entries` then verifies digests. Name for identity, evidence for
destruction. Rule 2 is satisfied.

**W4 — "The presets ownership check is weaker than the generator's."**
Withdrawn. `preset-detection-truth.test.js` pins both halves: a tool-owned directory under a *custom* name
is skipped only when it holds a marker, and a plain directory named `generated/` is **still** documentation
— "the skip must require ownership evidence, not a name."

## Open findings

### High

**H1. A credential in an unbalanced quote is emitted in clear, silently.** **[verified]**
`src/security/redact.ts:748-757` leaves a line untouched when masking would make its quotes unbalanced,
rather than emitting broken code. That trade is right. What is not right: the branch records **no
finding**, so `totals.redactedLines`, `reports/audit.md` and `manifest.warnings` all stay silent.

| Input | Result |
| :--- | :--- |
| `API_KEY="zq7Xk2nvalue"` | masked, 1 finding |
| `API_KEY="zq7Xk2nvalue` | **leaked, 0 findings** |
| `API_KEY='zq7Xk2nvalue` | **leaked, 0 findings** |
| `const API_KEY = "zq7Xk2nv` (source) | **leaked, 0 findings** |
| `API_KEY="zq7Xk2nvalue"` with `\"` | masked, 1 finding |

The source-file case is the one that matters: snapshots are dense with source, and a string continuing on
the next line hits it. No test covers this branch (`grep tests/ balanced|unbalanced` → nothing). The suite
tests the *opposite* direction thoroughly — `masking-and-config-honesty` A17 forbids the mask from widening
past the matched span.
**Fix:** `recordFinding` in that branch, even if the rewrite is still skipped.

### Medium

**H2. `validate` does not verify the completeness contract at all.** **[verified]**
Ten tampering variants of a real `incomplete[]` record, each reported **"valid and up to date"**:

```
incomplete[] emptied, count kept     -> exit 0 VALID      omittedRanges = "not-an-array" -> VALID
incomplete[] and count emptied       -> exit 0 VALID      omittedRanges = [[1,1]]        -> VALID
incompleteCount = 42                 -> exit 0 VALID      incomplete[0].reason = bogus  -> VALID
includedLines = 99999                -> exit 0 VALID      truncationReason = bogus      -> VALID
omittedLines = 0                     -> exit 0 VALID      relativePath = "../escape.ts" -> VALID
```

The last row is security-relevant: `files[].relativePath = "../x"` **is** refused ("resolves outside the
repository and was not inspected"), and so is `parts[].filename` ("bare filename") — but
`incomplete[].relativePath` is unguarded. Two of the three arrays with a path are confined.
The shape guard (`describeManifestShapeProblem`) checks existence and format of `fingerprint`,
`generatedAt`, `schemaVersion`, `totals` and `parts` — a field list that predates the 0.10 completeness
contract. AGENTS.md rule 5's guard (`verifyInMemory`) runs at *generation* time; once `manifest.json` is on
disk it is an **input**, and `validate` is the only thing that reads it as one.

**H3. The monolith claims `inclusionMode: "full"` while carrying a truncation reason and ranges.** **[verified]**
`src/index.ts:2907-2917` forces `inclusionMode: "full"` and `isPreviewTruncated: false` on the monolith
entry but leaves `truncationReason` and `omittedRanges` intact. Reproduced: `src/many.ts | mode full | reason
large-file-budget | ranges [[21,890]]`. A consumer filtering on `inclusionMode` sees a complete file.
Two tests look directly at this field and stop one assertion short: `generation-truth` asserts
`inclusionMode === "full"` and never reads the reason; `changed-scope` uses a *skeleton* file, where no
range exists.

**H4. `discovery` is missing from the user-facing config type.** **[verified]**
`SnapshotConfig` (`types.ts:538-608`) has no `discovery`, while `ResolvedSnapshotConfig` (:629) and
`CliOptions` (:683) both do. `defineConfig(config: SnapshotConfig)` and `resolveConfig(userConfig:
SnapshotConfig | null, …)` are the signatures a user writes against, so `snapshot.config.ts` containing
`discovery: "walk"` is **TS2353** — in the config format `init` recommends for TypeScript projects. The JSON
key works, the flag works, `CONFIG_KEYS` has it, and `describe` documents it. Every test is `.js`, so no
test can see a type.
**Fix:** one line in the interface, or a `keyof` assertion so the two cannot drift.

**H5. `snapshot_plan` blocks the MCP event loop; the worker is applied to one of two call sites.** **[verified]**
`src/mcp/generate-worker.ts` exists because *"a synchronous generate blocks the stdio server for about 7.5
seconds on a 3,000-file repository … a client with a socket timeout reports a working tool call as a dead
server."*
```
tools.ts:477  snapshot_generate -> await generateInWorker(...)      off-thread
tools.ts:388  snapshot_plan     -> generateSnapshot(config, {dryRun:true})   ON the RPC thread
```
Not a call swap: the worker receives `cliOptions`, and `dryRun` is not one, so the flag must be threaded
through. Same shape as H6 and N5 — the mechanism exists and is applied to one of several sites.

**H6. The import index omits previewed files, so the manifest contradicts its own file list.** **[verified]**
A previewed importer is included *because* it imports the change, yet the index records no such edge:
```
files[] contains big-consumer : true      indexes.imports.byFile : ["src/changed.ts"]   (absent)
big-consumer has a summary    : false     indexes.imports.centralFiles : []
snapshot_dependents(changed.ts, imported-by) -> []   "0 importer(s)"
```
`buildIndexes` (`index.ts:463`) filters on `isSourceSummary`, so a previewed file cannot enter `byFile`, and
it never receives `skippedSummaryImports` — which `index.ts:2476` *does* use for the `--with-dependents` hop
in the same run. `snapshot_dependents` reads `byFile` (`tools.ts:813,827`).
The only test that touches this (`mcp-dependents.test.js:110-115`) compares the tool to `centralFiles` —
both read the same index, so it passes while both are wrong.

**H7. `diff` cannot apply custom secret rules, so a declared token prints in clear.** **[verified]**
`compareManifests(before, after)` has no rules parameter and its only caller (`cli.ts:1681`) passes two
manifests. All three masking calls in `diff.ts` (:97, :126, :332) omit the rules argument, so they use the 31
built-ins. `generate`, `validate`, `explain` and MCP all apply the user's resolved `secretRules`. A
repository that declares a project token in `secretRules` — the reason the setting exists — gets it printed
by `diff`.

**H8. A custom `outDir` is generated into but never gitignored.** **[verified]**
`init --yes --out-dir .context` writes `/snapshot/` and `/snapshot.tmp/` (`init.ts:458`, a constant) while
generating into `.context`. `git status` → `?? .context/`; `git check-ignore` → exit 1. Applies to `setup`
too, which appends the same constant regardless of `resolved.outDir`.
Three tests assert the entries and all three miss it: `units.test.js:855` (`includes("snapshot/")`),
`setup-command.test.js:59-61` and `init-gitignore-directory.test.js:58` (`/snapshot\//`) — every pattern
matches both the anchored and unanchored form, and every test uses the default `outDir`.

**H9. Two live assets 404 on the published site.** **[verified]**
`https://ankurhalder.github.io/codebase-snapshot/` serves `src="docs/assets/favicon.svg"` and
`src=".../how-it-works.svg"` → **404**; `assets/…` → 200. `scripts/build-site.mjs:362` strips the raw-URL
prefix leaving `docs/assets/…`, while `:593-597` copies to `site/assets/`.
The gates cannot see it: `check-site-links` resolves `href` files and fragments only, `audit-site` checks
alt text and `og:image`, and `pages.yml` runs only those two. The assets themselves are correct — `favicon.svg`
is 32×32, `how-it-works.svg` 880×380, `social-card.png` exactly 1200×630.

**H10. A nested `.DS_Store` makes the tool refuse its own output directory.** **[verified]**
`snapshot/.DS_Store` → exit 0, replaced. `snapshot/reports/.DS_Store` → **exit 1**, "Refusing to replace
outDir … it carries this generator's ownership marker". `index.ts:1240` compares the **full relative path**
against `IGNORABLE_ENTRIES = {".DS_Store"}`, while `markerInventory` (:826) and `verifyMarkerInventory` (:1077)
compare the **basename** — four of five sites agree. On macOS, `open snapshot/` in Finder writes those files,
and the next run then treats its own directory as foreign.
`ownership-evidence.test.js:87-97` tests `.DS_Store` at the top level only. **Fix:** slice to the basename.

**H11. `generatorOrigin` prints a false origin for a BOM'd `package.json`.** **[verified]**
`cli.ts:903` uses a bare `JSON.parse` inside a `try` whose `catch` swallows everything:
```
plain package.json   -> 0.10.1 (project dependency ^0.10.1)   correct
BOM + package.json   -> 0.10.1 (global or direct install)      WRONG
```
That is the exact state the line exists to warn about — "a snapshot whose behaviour depends on the machine is
what a pin exists to prevent." `cli.ts:788-791`, **115 lines above**, does it correctly with `stripJsonComments`
and a comment naming this very failure. `records-and-bom.test.js` covers four other call sites; this is the
fifth, and the only unguarded `package.json` reader in the file.

**H12. SARIF result order depends on the host locale.** **[verified]**
`src/generator/sarif.ts:124` sorts with `localeCompare`. Three neighbours are locale-independent on purpose:
`terminal.ts:113` and `tokenize.ts:75` pin `toLocaleString("en-US")`, and `tree.ts:7` says "Ordering is a
plain code-unit comparison, **not** `localeCompare`". `redaction-reporting.test.js:138-157` asserts
`audit.md` and the README use three-digit grouping and contain no `1,00,` — so "same commit, different bytes
per machine" is a recognised, tested failure mode, for counts and for tree order but not for SARIF order.
Rule-ID stability *was* solved for the same reason (`sarif-integration.test.js:136-171`); order was not, and
no test asserts order — every assertion looks up by name or id.

## What is genuinely strong

Named because an audit that reports only defects is not useful either.

- **Ownership evidence is real.** A forged `{}` marker does not hide a directory; a directory holding only
  `.gitkeep` is refused and the refusal names the entry; a live-pid lock is never stolen ("a wrongly refused
  run costs a retry, a wrongly stolen lock costs a snapshot"); a failed cross-device copy never leaves a
  directory wearing a "complete" marker.
- **Six doc-to-code mechanisms exist** — DH-20 (explain strings), DH-21 (`appliesTo`), C-4 (create README),
  `repo-hygiene` (MCP tool count in 4 documents, CHANGELOG section, words eaten by control escapes),
  `token-estimate` (the published `bytes/3.5` rule). N5's three items sit outside all six.
- **Three source-text assertions** where no behavioural signal exists: `pathScanRules` must not re-add the
  built-ins; no `execSync`, and every `execFileSync` passes the shared ceiling; no comparison operator may be
  lost to redaction.
- **Redaction is tested from three mutually hostile directions** — leaks (fragments, percent-encoded JWT,
  PEM blocks), data loss (regex literals, prose, `tokenize.ts` as its own fixture), and over-redaction
  (URL hosts, key-name lists).
- **The suite polices itself:** `temp-hygiene` fails any test that creates a scratch directory it never
  removes, and proves the wrapper by running a deliberately leaky child.
- **Tests distinguish acceptance from effect:** "the flag is not ignored", "the EXDEV path really ran", the
  0555 probe, `assertAllKeys`.
- `manifest-accounting` reconciles every file's bytes and lines against the emitted block; `partitioner-budget`
  sweeps every budget; `redaction-bridging` proves no part leaves a fence open.

## Recommended order

1. **H1** — record the finding on the quote-balance branch. One line; closes a silent credential leak.
2. **H2** — extend the shape guard to `incomplete[]` and confine its `relativePath`. Closes ten tampering
   routes including the only unguarded path array.
3. **H10**, **H11**, **H8** — three one-line fixes (basename; `stripJsonComments`; thread `outDir` into the
   ignore entries) that remove three ways the tool contradicts itself.
4. **H9** — fix the two asset paths and widen the link gate to `src`.
5. **H3**, **H6**, **H7**, **H12** — clear the monolith's fragment fields, thread `skippedSummaryImports` into
   `buildIndexes`, give `compareManifests` a rules parameter, and compare code units in SARIF.
6. **H4**, **H5** — the type line and the worker's `dryRun`.
7. Nits in the order they appear.
